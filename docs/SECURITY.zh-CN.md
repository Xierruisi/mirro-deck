# 安全政策

**简体中文** | [English](SECURITY.md)

## 支持范围

MirroDeck 目前只为最新正式发布版本和 `main` 分支提供安全修复。旧版本用户应先升级到最新版本，再确认问题是否仍然存在。

## 私下报告漏洞

请勿通过公开 Issue、Discussion 或 Pull Request 披露尚未修复的安全问题。请在仓库的 **Security → Advisories → Report a vulnerability** 中创建 GitHub Security Advisory，私下向维护者报告。

报告中请尽量包含：

- 受影响的 MirroDeck 版本、操作系统、架构与安装包类型；
- 问题影响、复现步骤和最小化验证代码；
- 相关日志、截图或崩溃信息；
- 可行的缓解或修复建议（如有）。

提交前请移除设备序列号、IP 地址、访问令牌、签名密钥及其他敏感信息。维护者会先确认收到报告，再通过该 Advisory 沟通验证、修复与披露安排；请在双方完成协调披露前保持问题私密。

若问题来自 scrcpy、ADB 或其他上游组件，也欢迎报告其对 MirroDeck 的具体影响。对上游组件本身的漏洞，请同时遵循对应项目的安全报告流程。

## 善意研究

请只测试自己拥有或已获授权的设备和数据，不进行破坏性测试、隐私侵害或服务中断。对遵守本政策并善意报告的问题，项目会尽力配合调查与修复。
