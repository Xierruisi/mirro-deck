# MirroDeck 设备连接教程

**简体中文** | [English](connection-guide.md)

MirroDeck 支持通过 USB、Wi-Fi 或 Android 模拟器连接设备。连接成功后，设备会出现在应用左侧的设备列表中；状态显示为“可用”时即可开始投屏。

> MirroDeck 已内置 scrcpy 和 adb，正常使用安装包时不需要另外安装 Android Platform Tools。

## 连接前准备

1. 在 Android 设备上打开“设置 → 关于手机”。
2. 连续点击“版本号”或“软件版本号”约 7 次，直到系统提示已进入开发者模式。
3. 返回设置，进入“开发者选项”并开启“USB 调试”。

不同品牌手机的菜单名称可能略有差异，可以在系统设置中搜索“版本号”“开发者选项”或“USB 调试”。

## 方式一：通过 USB 连接

USB 连接最稳定，建议首次使用时先通过此方式确认设备能够正常授权。

1. 使用支持数据传输的 USB 线连接电脑和 Android 设备。
2. 解锁设备，留意手机上出现的“允许 USB 调试”对话框。
3. 确认 RSA 指纹；如果是自己的电脑，可以勾选“始终允许使用这台计算机”，然后点击“允许”。
4. 打开 MirroDeck。应用会自动扫描设备，无需点击“添加设备”。
5. 等待设备出现在左侧列表，并确认状态为“可用 · USB”。
6. 选中设备，按需调整画质、控制和录屏选项，然后点击右上角的“开始投屏”。

投屏画面会在独立的 scrcpy 原生窗口中打开。点击 MirroDeck 中的“停止投屏”，或关闭投屏窗口，即可结束本次会话。

## 方式二：通过 Wi-Fi 连接（Android 11 及以上）

电脑和 Android 设备应连接到同一个局域网。首次使用需要先完成一次无线配对。MirroDeck 会持续启用安全的 ADB mDNS 发现，因此无线调试端口变化后，已配对设备通常也能自动重连。

### 第一步：无线配对

1. 在手机的“开发者选项”中打开“无线调试”。
2. 进入“无线调试”，点击“使用配对码配对设备”。
3. 在 MirroDeck 左下角点击“添加设备 → Wi-Fi 连接”。
4. 将手机配对弹窗中的“IP 地址和端口”填入 MirroDeck，例如 `192.168.1.10:37099`。
5. 输入手机显示的 6 位 Wi-Fi 配对码，然后点击“开始配对”。
6. 配对成功后，MirroDeck 会等待 ADB 通过 mDNS 发现并连接设备。左侧出现“可用 · Wi-Fi”后，即可选择设备并点击“开始投屏”。

配对码和配对端口通常只在短时间内有效。如果配对失败，请在手机上重新打开“使用配对码配对设备”，并使用新生成的信息。

### 手动连接兜底

如果当前局域网屏蔽了 mDNS，或者设备没有自动出现：

1. 回到手机的“无线调试”主页面，找到页面顶部显示的“IP 地址和端口”。
2. 使用自动发现失败后 MirroDeck 保留的连接表单。设备之前已经配对过时，选择“添加设备 → Wi-Fi 连接 → 已配对？直接进入连接”。
3. 输入无线调试主页面上的地址，然后点击“连接设备”。
4. 等待设备出现在左侧列表，并确认状态为“可用 · Wi-Fi”。
5. 选中设备并点击“开始投屏”。

> 配对地址和连接地址通常使用不同端口。配对时使用“使用配对码配对设备”弹窗中的地址；连接时使用“无线调试”主页面中的地址。

### 再次连接已配对设备

设备与电脑已经配对过时，通常不需要重新输入配对码：

1. 确保电脑和手机仍在同一个局域网，并在手机上开启“无线调试”。
2. 打开 MirroDeck；应用会通过持续运行的 ADB mDNS 发现自动重连设备。
3. 设备显示为“可用 · Wi-Fi”后，选中设备并开始投屏。

手机重新连接网络或重新开启无线调试后，端口可能变化；mDNS 会自动解析当前端口。若发现失败，请使用手机当前显示的地址进行手动连接。

### 一键扫描局域网设备

点击左侧设备列表右上角的刷新按钮，MirroDeck 会先刷新 ADB 当前设备，再扫描当前局域网中的 ADB mDNS 服务和传统 `5555` 端口。扫描到的候选设备会以“已发现 · Wi-Fi”显示；选择候选设备后点击“连接设备”即可尝试连接。

局域网扫描默认只探测当前网络接口所在的 `/24` IPv4 网段，并且不会自动完成无线调试配对。首次配对仍需在手机上打开无线调试配对页面，并输入六位配对码。访客网络、企业网络或路由器的客户端隔离也可能阻止发现设备。

## 方式三：连接 Android 模拟器

1. 先启动 Android Studio Emulator 或其他可通过 adb 访问的本地模拟器。
2. 打开 MirroDeck，或点击设备列表右上角的刷新按钮。
3. 等待名称类似 `emulator-5554` 的设备出现，并确认状态为“可用 · 模拟器”。
4. 选中模拟器并点击“开始投屏”。

## 同时镜像多台设备

MirroDeck 可以同时运行多台已授权设备的镜像会话：

1. 选择第一台状态为“可用”的设备，点击“开始投屏”。
2. 等待独立的 scrcpy 窗口打开后，在左侧选择另一台设备。
3. 对第二台设备再次点击“开始投屏”。
4. 左侧设备列表中的“实时”标记表示该设备当前有活动镜像会话。

每台设备对应一个独立的 scrcpy 进程和窗口。当前画质、音频、控制和窗口选项是全局默认配置：修改设置不会改变已经运行中的会话，但会影响之后启动的设备。当前不支持一键启动全部设备或批量停止。

## 如何判断连接状态

| 状态 | 含义 | 处理方式 |
|---|---|---|
| 可用 | 设备已连接并完成授权 | 可以直接点击“开始投屏” |
| 待授权 | 电脑尚未获得 USB 调试授权 | 解锁手机并确认“允许 USB 调试”对话框 |
| 离线 | adb 能看到设备，但无法正常通信 | 检查数据线或网络，然后在 MirroDeck 中点击“重启 ADB” |

## 常见问题

### USB 连接后没有发现设备

- 确认 USB 线支持数据传输，而不只是充电。
- 解锁手机，并将 USB 用途切换为“文件传输”后重试。
- 确认“开发者选项”和“USB 调试”均已开启。
- 点击设备列表右上角的刷新按钮。
- Windows 可能需要安装手机厂商提供的 ADB USB 驱动。
- Linux 可能需要配置 Android udev 规则，并将当前用户加入 `plugdev` 用户组。

### 设备一直显示“待授权”

1. 保持手机解锁，断开并重新连接 USB 线。
2. 在手机“开发者选项”中点击“撤销 USB 调试授权”。
3. 重新连接后，再次确认 RSA 指纹授权对话框。

### 无线配对成功，但设备没有出现

保持“无线调试”开启，并确认电脑和手机位于同一个局域网。访客、公司、校园或公共网络可能屏蔽 mDNS 或隔离客户端。点击“重启 ADB”并刷新一次；若设备仍未出现，请在手动连接表单中输入手机“无线调试”主页显示的连接地址。

### 无线连接失败

- 确认电脑和手机位于同一个局域网，且访客网络或路由器没有隔离设备。
- 确认使用的是无线调试主页面的连接端口，而不是配对弹窗中的端口。
- 关闭并重新开启手机的“无线调试”，使用新显示的地址再次连接。
- 如果设备显示“离线”，点击 MirroDeck 提示中的“重启 ADB”后重试。
- 公司、校园或公共 Wi-Fi 可能限制设备间通信，此时建议改用 USB。

### “开始投屏”按钮不可用

只有设备状态为“可用”时才能开始投屏。请先处理列表中的“待授权”或“离线”状态。如果是从源码运行项目，还需要先执行 `npm run tools:prepare` 准备内置工具链。

## 安全建议

- 只在可信局域网中开启无线调试，不要将无线调试端口暴露到公网。
- 使用结束后，可以关闭手机的“无线调试”。
- 在公共或不受信任的电脑上，不要勾选“始终允许使用这台计算机”；使用完毕后可撤销 USB 调试授权。
